# Lip-Reading AI 👄

A deep-learning app that **reads lips from silent video** — it watches a speaker's mouth and predicts the sentence they're saying, no audio required. A 3D-CNN + Bidirectional-LSTM model (a LipNet-style architecture) is trained on the **GRID corpus** and served through a **Streamlit** web app, gated behind **Firebase** email/password authentication.

The model takes 75 video frames of a cropped mouth region and outputs the spoken sentence as text using CTC (Connectionist Temporal Classification) decoding.

---

## Tech Stack

| Layer | Technology |
|---|---|
| **Model** | TensorFlow / Keras — LipNet-style 3D CNN + Bidirectional LSTM + CTC |
| **Video processing** | OpenCV (frame extraction), ffmpeg (re-encode for browser playback), imageio (preview GIF) |
| **Web UI** | Streamlit (+ `streamlit-option-menu` for the sidebar) |
| **Auth** | Firebase Admin SDK (email/password sign-up & login) |
| **Dataset** | GRID audiovisual corpus (speaker `s1`) |
| **Language** | Python 3.10 |

## How It Works

```
   🎥 Video of a speaker (.mpg / .mp4)
        │
        ▼
   utils.load_video()        ← OpenCV reads every frame, converts to grayscale,
        │                       crops the MOUTH region [190:236, 80:220],
        │                       normalizes (subtract mean / divide by std)
        ▼
   75 frames × 46 × 140 × 1  (the only thing the model "sees")
        │
        ▼
   modelutil.load_model()    ← 3×(Conv3D → ReLU → MaxPool3D)
        │                       → TimeDistributed(Flatten)
        │                       → 2× Bidirectional LSTM (128, dropout 0.5)
        │                       → Dense(41, softmax)
        │                       weights loaded from models/checkpoint
        ▼
   CTC decode (tf.keras.backend.ctc_decode)
        │
        ▼
   num_to_char → "place blue at f two now"   (predicted sentence)
```

1. **Pre-processing** ([utils.py](utils.py)): each frame is grayscaled and cropped to a fixed mouth window, then the clip is standardized. A character vocabulary (`a–z`, `'?!`, digits, space) maps characters ↔ integers via Keras `StringLookup`.
2. **Model** ([modelutil.py](modelutil.py)): a `Sequential` network — three 3D convolution blocks extract spatio-temporal mouth features, two stacked BiLSTMs model the sequence, and a softmax over 41 classes (vocabulary + CTC blank) produces per-frame character probabilities. Trained weights are restored from `models/checkpoint`.
3. **Decoding**: CTC greedy decoding collapses the 75-step probability sequence into the final character string, which is joined back into words.
4. **UI** ([streamlitapp.py](streamlitapp.py)): pick a video from the GRID `s1` set; the app shows the original clip, the grayscale mouth-crop the model actually sees (as a GIF), the raw predicted tokens, and the decoded sentence next to the ground-truth alignment.
5. **Auth gate** ([implementation1.py](implementation1.py)): a separate Streamlit entry point handles Firebase sign-up/login; on a successful login it launches `streamlitapp.py`.

## Architecture / File Map

| File | Role |
|---|---|
| [streamlitapp.py](streamlitapp.py) | **Main app.** Lets you choose a GRID video, runs the model, and displays the input, the mouth-crop preview, raw tokens, and the decoded vs. ground-truth sentence. |
| [modelutil.py](modelutil.py) | Builds the LipNet-style Keras model and loads the trained weights from `models/checkpoint`. |
| [utils.py](utils.py) | Video → tensor pipeline (load, grayscale, mouth crop, normalize), GRID alignment (`.align`) parsing, and the char↔int vocabulary mappings. |
| [implementation1.py](implementation1.py) | Firebase auth front door (sign-up / login) that launches the main app after login. |
| [rough_work.py](rough_work.py) | Unrelated scratch file (a small OpenAI ChatGPT-clone demo); not part of the lip-reading pipeline. |
| `models/checkpoint*` | Trained model weights (~100 MB) loaded by `modelutil.load_model()`. |
| `test_video.mp4` | A browser-playable copy of the last selected clip (regenerated by ffmpeg at runtime). |
| `animation.gif` | The grayscale mouth-crop preview generated for the UI. |
| `lipreadingaiauth-*.json` | Firebase service-account credentials (**you must provide your own — see below**). |

## Installation & Setup

### Prerequisites
- **Python 3.10** (the bundled `.pyc` files target 3.10)
- **ffmpeg** installed and on your PATH — `brew install ffmpeg` (macOS) / `apt install ffmpeg` (Linux)
- The **GRID corpus** data for speaker `s1` (not included — see step 4)
- A **Firebase project** with Email/Password auth enabled (only needed for `implementation1.py`)

### 1. Create a virtual environment
```bash
cd Lip-Reading-Ai
python3.10 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
```

### 2. Install dependencies
No manifest ships with the repo; install the required packages directly:
```bash
pip install tensorflow opencv-python imageio streamlit streamlit-option-menu \
            firebase-admin pyautogui
```
> On Apple Silicon, use `tensorflow-macos` (and optionally `tensorflow-metal`) instead of `tensorflow`.

### 3. Confirm the model weights
The trained weights live in `models/`:
```
models/checkpoint
models/checkpoint.data-00000-of-00001
models/checkpoint.index
```
These are already present in the repo. (The `models/__MACOSX/` folder is macOS zip cruft and can be deleted.)

### 4. Add the GRID dataset
The app reads videos from a `data/` folder that is **not** included:
```
data/
  s1/                  ← GRID speaker s1 videos (.mpg)
  alignments/s1/       ← matching .align ground-truth files (used by utils.load_data)
```
Download the GRID corpus (speaker `s1`) and place the files as shown above.
> Note: `streamlitapp.py` reads from `./data/s1`, while `utils.load_data()` resolves paths relative to `../data/...`. Make sure your `data/` location matches how you launch the app, adjusting the paths if needed.

### 5. Configure Firebase (only for the auth gate)
`implementation1.py` expects a Firebase service-account key at
`lipreadingaiauth-e45d0bba0b3e.json` (the file in the repo is intentionally **empty** — the real credentials are a secret and must not be committed).

1. In the [Firebase console](https://console.firebase.google.com/), create a project and enable **Authentication → Email/Password**.
2. **Project settings → Service accounts → Generate new private key.**
3. Save the downloaded JSON over `lipreadingaiauth-e45d0bba0b3e.json` (or update the filename referenced in `implementation1.py`).

## Running the App

**Option A — straight to the lip-reading demo (no login):**
```bash
streamlit run streamlitapp.py
```

**Option B — with the Firebase auth gate:**
```bash
streamlit run implementation1.py
```
Sign up / log in; on success it launches the main demo.

Then pick a video from the dropdown and the app shows the prediction.

## Notes & Limitations
- **Dataset required**: the repo ships the model but not the GRID videos — the dropdown is empty until you add `data/s1`.
- **Fixed input geometry**: the mouth crop (`[190:236, 80:220]`) and 75-frame length are tuned for GRID-format clips; other videos need re-cropping/resampling to match `(75, 46, 140, 1)`.
- **Vocabulary**: the model only knows the GRID character set (lowercase letters, a few symbols, digits, space) — it's a constrained-grammar lip reader, not general-purpose.
- **`pyautogui` dependency**: `implementation1.py` uses `pyautogui.hotkey(...)` after launching the app, which needs a desktop GUI session (won't work headless).
- **Secrets**: never commit a real `lipreadingaiauth-*.json`. The empty placeholder in the repo is deliberate.
- `rough_work.py` is leftover experimentation and unrelated to lip reading.
